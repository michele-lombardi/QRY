# QRY v0.2.1 — macOS memory fix

This corrective release fixes unbounded native memory growth in QRY's macOS
overlay. A long-running `v0.2.0-2` process was observed using approximately
**5.49 GB** after temporary screen-description objects accumulated on its
background placement thread.

## What changed

- Release temporary Cocoa objects after every overlay placement refresh.
- Require Tauri 2.12.5 or newer, with monitor queries dispatched to the main thread.
- Add a worker-lifetime ownership test and a permission-free native monitor
  memory regression probe.
- Include physical footprint in macOS resource measurements, so compressed
  allocations cannot be hidden by low RSS readings.
- Restore macOS CI and release builds using the supported `macos-15` runner.

The release also includes the prepared Tauri/frontend dependency refresh and
keeps the existing autostart integration at 2.6 pending its separate migration
checks. No statistics reset or database migration is required.

## Verification

On Apple Silicon with macOS 26.6.2, the accelerated probe completed **20,000
display refreshes** with sampled native physical footprint around **20 MB** and
no growth above the warmup baseline. The native ownership test also checks that
temporary objects are released during the worker's lifetime.

The [technical bug report](https://github.com/michele-lombardi/QRY/blob/v0.2.1/docs/bugs/macos-overlay-memory-leak.md)
contains the allocation counts, exact measurements, cause, regression commands,
and remaining real-device validation. The accelerated probe is not a completed
multi-hour full-app soak. Live input validation after the local rebuild remains
pending renewed macOS consent.

## Updating

1. Quit the previous QRY instance normally. The old process must exit to release
   memory it has already accumulated.
2. Download the corrected build for your architecture and its `.sha256` file,
   verify the checksum, and replace the application.
3. Reopen QRY. A rebuilt ad-hoc-signed macOS executable may need Input Monitoring
   authorization again. If QRY is listed as allowed but reports no access, turn
   its entry off and on in **System Settings → Privacy & Security → Input Monitoring**.
4. Complete QRY's setup, renew optional Accessibility access if needed, choose
   the desired start-at-login setting, and let QRY restart.

See the [installation guide](https://github.com/michele-lombardi/QRY/blob/v0.2.1/docs/installation.md)
for detailed installation and permission instructions.

## Release status and remaining checks

This release is prepared as a **draft**. Before publication, complete the
real-device release checklist, including renewed macOS input consent, live typing,
multi-hour memory sampling, sleep/wake, monitor changes, Intel hardware, and a
clean Windows installation. The accelerated native-query check covers the leak's
allocation path and does not replace those lifecycle checks.

The existing beta signing limitations apply: macOS bundles are ad-hoc signed and
not notarized; Windows installers may be unsigned. The native capsule requires
macOS 14 or newer.
